# Source-neutral base (November 12 refinement)

Supersedes Bluesky-only architecture assumptions, not historical notes. Hosting remains Supabase, intended hourly cadence. No source roster or topics are activated. Retain existing topic lists for later; political news is excluded from the eventual editorial scope, with possible local-news exceptions requiring selection later.

`functions/_shared/pipeline.mjs` defines a credential-free adapter boundary: configured adapter -> public evidence items -> common review candidates. Tested with synthetic RSS/HN/newsletter adapters; these are contract fixtures, **not implemented network integrations**. Adapter registry is trusted code, not arbitrary URLs or executable modules supplied by callers. Empty selection produces an idle/no-publish result. Adapter failures are isolated. Private newsletter messages cannot enter this public evidence contract; a future newsletter adapter must separately extract/verify public article evidence, not export email content. Gmail access is not implemented.

Each item carries source kind/id, stable origin identifier, author, evidence URL, timestamp and raw evidence text. Namespaced identifiers avoid cross-provider item-ID collisions; existing canonical-link story hashes can deduplicate items across adapters. Story grouping should retain all evidence references rather than discard corroborating sources. The old `bluesky-collect` endpoint is a review-only prototype and has **not** yet been rewired to this generic runner. Its persistence proposal drops source_type/source_id today; schema evolution and integration tests are required before deploying the neutral runner.

Intended stages: collect -> normalize -> persistent dedup/group -> verify primary evidence -> rank meaningful changes -> compose short original summary + why it matters + source link -> editorial/authorization gate -> publish. Raw source text is evidence, not an approved post. No blind reposting. Keyword matches alone are not editorial selection. Summary generation, political-topic filtering, relevance judgment, multi-source corroboration and publisher are deliberately not implemented or claimed complete.

Future RSS, HN and Bluesky adapters must enforce bounded response/time limits and fixed/approved public destinations; RSS requires SSRF protections including resolved IP checks and redirect control. Avoid untrusted source instructions. Newsletter transport and secrets stay separate. Add adapters incrementally with recorded fixtures and contract tests. No credentials, sources, model costs, schedules or public posts are activated by this change.

Next integration work after source/content scope is settled: generic deployed entrypoint and selected adapter registry; multi-source evidence storage; end-to-end database tests; curation quality tests; then a separately gated publisher with atomic claims, deterministic keys and uncertain-outcome reconciliation. Existing audio function and cron jobs remain unchanged.
